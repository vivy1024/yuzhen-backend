### UserProfile.php 🆕 v2.0.0 前后端对齐

**路径**: `app/Modules/User/Models/UserProfile.php`

**版本**: v2.0.0 (2025-11-08) - 完全JSON结构存储，对齐前端TypeScript类型

**表结构**:
```sql
CREATE TABLE user_profiles (
    id BIGINT PRIMARY KEY,
    user_id BIGINT UNIQUE,
    basic_info JSON,              -- 基础信息（嵌套结构）
    fitness_goals JSON,            -- 健身目标（嵌套结构）
    training_preferences JSON,     -- 训练偏好（嵌套结构）
    health_status JSON,           -- 健康状况（嵌套结构）
    nutrition_profile JSON,       -- 营养档案（嵌套结构）
    strength_data JSON,           -- 力量数据（可选，嵌套结构）
    ffmi_assessment JSON,         -- FFMI评估（可选，嵌套结构）
    version INT DEFAULT 1,        -- 版本号（冲突检测）
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_profiles_user_id (user_id)
);
```

**核心字段说明**:
- `basic_info`: 包含昵称、年龄、性别、身高、体重、体脂率、健身水平等基础信息
- `fitness_goals`: 包含主要目标、次要目标、训练分化等
- `training_preferences`: 包含可用器械、训练场地、运动偏好等
- `health_status`: 包含慢性疾病、伤病史、用药情况等
- `nutrition_profile`: 包含饮食偏好、过敏食物、补剂使用等
- `strength_data`: 包含6大基础力量动作的1RM/3RM数据（非初学者）
- `ffmi_assessment`: 包含FFMI计算结果、评估等级、训练建议等

public function toArray(Request $request): array
{
    $profile = $this->resource;

    return [
        // 用户ID

        'basic_info' => $profile->basic_info ?? null,

        // 健身目标（必填）
        'fitness_goals' => $profile->fitness_goals ?? null,

        // 训练偏好（必填）
        'training_preferences' => $profile->training_preferences ?? null,

        // 力量数据（非初学者才有）
        'strength_data' => $profile->strength_data ?? null,

        // 健康状况（必填）
        'health_status' => $profile->health_status ?? null,

        // 营养档案（必填）
        'nutrition_profile' => $nutrition_profile ?? null,

        // FFMI评估结果（可选）

        'created_at' => $profile->created_at?->toISOString(),

## 🔄 数据流转

### 用户注册流程（与Auth模块配合）

```
1. Auth模块：用户注册
   ↓
2. 创建User记录
   ↓
3. 触发UserRegistered事件
   ↓
4. UserService监听事件
   - 创建默认UserProfile
   - 分配免费会员
   - 发送欢迎邮件
   ↓
5. 返回用户信息和Token
```

### 用户档案更新流程

```
1. 前端提交档案修改
   ↓
2. UpdateProfileRequest验证数据
   ↓
3. UserService::updateProfile()
   - 更新用户基本信息
   - 更新用户档案
   - 重新计算BMI
   ↓
4. 触发UserProfileUpdated事件
   ↓
5. 返回更新后的用户信息
```

### 上传处理

```php
// UserService::updateAvatar()
public function updateAvatar(int $userId, UploadedFile $file): string
{
    // 验证文件
    $file->validate([
        'mimes:jpeg,png,jpg,gif',
        'max:2048', // 2MB
    ]);
    
    // 生成文件名
    $filename = "user-{$userId}." . $file->extension();
    
    // 存储文件
    $path = $file->storeAs('avatars', $filename, 'public');
    
    // 更新用户记录
    $user = User::find($userId);
    $user->avatar = $path;
    $user->save();
    
    return $user->avatar_url;
}
```

// 在更新头像前删除旧头像

}

## 🤖 MCP集成 (v1.1.0新增)

### Internal API - 为MCP提供用户档案

**Controller**: `app/Modules/User/Controllers/InternalUserController.php`

**路由**: `GET /api/internal/user-profile/{userId}`

**认证**: `X-Internal-Token` header (必须与 `.env` 中的 `INTERNAL_API_TOKEN` 一致)

**用途**: 允许MCP/CrewAI等内部服务访问用户档案数据，无需用户Token

**⚠️ 重要修复 (v1.1.1)**:
- 🐛 **问题**: `InternalUserController` 使用对象访问方式 (`$user->profile`) 访问数组数据
- ✅ **原因**: `UserService::getDetail()` 返回数组类型，但代码使用了对象访问语法
- ✅ **修复**: 将所有 `$profile->xxx` 改为 `$profile['xxx'] ?? null`，确保类型安全
- ✅ **影响**: 修复后MCP可以正常获取用户档案，避免 "Attempt to read property on array" 错误
