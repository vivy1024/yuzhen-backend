## 📋 概述

BUILD_BODY项目采用**双数据源架构**来存储和使用1603个健身动作数据：

```
1603动作库
    ├── MySQL (PHP后端) - 关系型存储，CRUD操作
    └── Neo4j (MCO知识图谱) - 图数据库，AI推理
```

### 为什么需要双数据源？

| 需求 | MySQL适用 | Neo4j适用 |
|-----|----------|----------|
| **标准CRUD** | ✅ 快速查询 | ❌ 过于复杂 |
| **分页列表** | ✅ 简单高效 | ❌ 不必要 |
| **筛选排序** | ✅ SQL强大 | ❌ Cypher复杂 |
| **关系推理** | ❌ JOIN性能差 | ✅ 图遍历高效 |
| **路径查询** | ❌ 递归困难 | ✅ 原生支持 |
| **相似推荐** | ❌ 需额外算法 | ✅ 图算法内置 |
| **知识图谱** | ❌ 不支持 | ✅ 核心功能 |

## 📦 数据分布详情

### 1. MySQL数据结构 (PHP后端)

#### 主表: exercises

```sql
CREATE TABLE exercises (
    id BIGINT PRIMARY KEY,
    name VARCHAR(255),                  -- 英文名称
    name_zh VARCHAR(255),               -- 中文名称
    slug VARCHAR(255) UNIQUE,           -- URL标识
    description TEXT,                   -- 英文描述
    description_zh TEXT,                -- 中文描述
    primary_muscles VARCHAR(255),       -- 主要肌群
    equipment VARCHAR(255),             -- 所需器械
    difficulty VARCHAR(50),             -- 难度等级
    force_type VARCHAR(50),             -- 力量类型
    mechanic_type VARCHAR(50),          -- 机制类型
    grips JSON,                         -- 握法（JSON）
    categories JSON,                    -- 分类（JSON）
    rating INT DEFAULT 0,               -- 评分
    view_count INT DEFAULT 0,           -- 浏览次数
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 索引优化
CREATE INDEX idx_primary_muscles ON exercises(primary_muscles);
CREATE INDEX idx_equipment ON exercises(equipment);
CREATE INDEX idx_difficulty ON exercises(difficulty);
CREATE FULLTEXT INDEX idx_search ON exercises(name, name_zh, description, description_zh);
```

#### 关联表

```sql
-- 媒体资源表 (19,236条记录)
exercise_v2_media (
    id, exercise_id, media_type, cdn_url, local_path, file_size, duration, display_order
)

-- 指导步骤表 (4,932条记录)
exercise_v2_instructions (
    id, exercise_id, instruction_type, step_number, content_en, content_zh
)

-- 次要肌肉群表 (668条记录)
exercise_v2_secondary_muscles (
    id, exercise_id, muscle_name, muscle_name_zh
)

-- 标签表 (4,126条记录)
exercise_v2_tags (
    id, exercise_id, tag_name, tag_name_zh
)
```

**总记录数**: ~30,000条记录

### 2. Neo4j图结构 (MCO知识图谱)

#### 节点类型 (Labels)

```cypher
// 动作节点 (1603个)
(:Exercise {
    id: "exercise_123",
    name_en: "Bench Press",
    name_zh: "卧推",
    difficulty: "intermediate",
    equipment: "barbell",
    force_type: "push",
    mechanic_type: "compound",
    rating: 5,
    view_count: 1520
})

// 肌肉节点 (20+个)
(:Muscle {
    id: "muscle_chest",
    name_en: "Chest",
    name_zh: "胸肌",
    muscle_group: "upper_body"
})

// 器械节点 (15+个)
(:Equipment {
    id: "equipment_barbell",
    name_en: "Barbell",
    name_zh: "杠铃"
})

// 难度节点 (3个)
(:Difficulty {
    id: "difficulty_beginner",
    level: "beginner",
    name_zh: "初级"
})
```

#### 关系类型 (Relationships)

```cypher
// 主要肌群关系
(Exercise)-[:TARGETS_PRIMARY {strength: 1.0}]->(Muscle)

// 次要肌群关系
(Exercise)-[:TARGETS_SECONDARY {strength: 0.5}]->(Muscle)

// 使用器械关系
(Exercise)-[:USES_EQUIPMENT]->(Equipment)

// 难度关系
(Exercise)-[:HAS_DIFFICULTY]->(Difficulty)

// 动作替代关系
(Exercise)-[:ALTERNATIVE_TO {similarity: 0.85}]->(Exercise)

// 强度标准关系
(Exercise)-[:HAS_STRENGTH_STANDARD]->(StrengthStandard)
```

#### 图数据示例

```cypher
// 查询示例：找出所有针对胸肌的中级动作
MATCH (e:Exercise)-[r:TARGETS_PRIMARY]->(m:Muscle {name_zh: "胸肌"})
WHERE e.difficulty = "intermediate"
RETURN e, r, m
LIMIT 10

// 推荐示例：找出与卧推相似的动作
MATCH (e1:Exercise {name_zh: "卧推"})-[:ALTERNATIVE_TO]-(e2:Exercise)
RETURN e2
ORDER BY e2.rating DESC
LIMIT 5

// 路径查询：找出训练胸肌的完整动作链
MATCH path = (e:Exercise)-[:TARGETS_PRIMARY]->(m:Muscle {name_zh: "胸肌"})
                      -[:PART_OF]->(mg:MuscleGroup)
RETURN path
```

```python
# ✅ 基于用户档案推荐动作
def recommend_exercises(user_profile: dict) -> list:
    """
    考虑因素:
    - 用户目标肌群
    - 健身水平
    - 可用器械
    - 历史训练记录
    - 动作相似度
    """
    query = """
    MATCH (e:Exercise)-[:TARGETS_PRIMARY]->(m:Muscle)
    WHERE m.name_zh IN $target_muscles
      AND e.difficulty = $user_level
      AND e.equipment IN $available_equipment
    RETURN e
    ORDER BY e.rating DESC
    LIMIT 10
    """
```

#### 2. 关系推理

```python
# ✅ 找出替代动作（如：杠铃卧推 → 哑铃卧推）
def find_alternatives(exercise_id: str, reason: str = "injury") -> list:
    """
    考虑因素:
    - 目标肌群相同
    - 难度相近
    - 器械可替换
    - 动作模式相似
    """
    query = """
    MATCH (e1:Exercise {id: $exercise_id})
    MATCH (e2:Exercise)
    WHERE e1 <> e2
      AND EXISTS((e1)-[:ALTERNATIVE_TO]-(e2))
    RETURN e2, e2.similarity as similarity
    ORDER BY similarity DESC
    """
```

#### 3. 路径查询

```python
# ✅ 找出从初级到高级的动作进阶路径
def find_progression_path(start_exercise: str, goal: str) -> list:
    """
    示例: 俯卧撑 → 上斜俯卧撑 → 标准卧推 → 杠铃卧推
    """
    query = """
    MATCH path = shortestPath(
        (start:Exercise {id: $start_exercise})
        -[:PROGRESSES_TO*1..5]-
        (end:Exercise)
    )
    WHERE end.difficulty = $goal_difficulty
    RETURN path
    """
```

```php
✅ 使用场景:
```

```python
def recommend_by_graph(user_goals: list) -> list:
    query = """
```
