## 🔄 请求流程

### 典型的API请求流程：

```
1. 用户请求
   GET /api/exercises?muscle=chest&page=1
        ↓
2. 路由解析
   routes/modules/exercise.php
        ↓
3. 控制器
   ExerciseController::index()
        ↓
4. 请求验证
   FilterExerciseRequest
        ↓
5. 业务逻辑
   ExerciseService::getList()
        ↓
6. 缓存检查
   ExerciseCacheService
        ↓
7. 数据访问
   ExerciseRepository::paginate()
        ↓
8. 数据转换
   ExerciseResource::collection()
        ↓
9. 统一响应
   BaseController::page()
        ↓
10. JSON响应
    ApiResponse::page()
```

## 🎨 设计模式

### 1. 依赖注入模式

```php
// Service注入Repository接口
class ExerciseService
{
    public function __construct(
        ExerciseRepositoryInterface $repository,
        ExerciseCacheService $cacheService
    ) {
        $this->repository = $repository;
        $this->cacheService = $cacheService;
    }
}

// 在ServiceProvider中绑定
$this->app->bind(
    ExerciseRepositoryInterface::class,
    ExerciseRepository::class
);
```

### 2. 仓储模式（Repository Pattern）

```php
// 定义接口
interface ExerciseRepositoryInterface
{
    public function findById(int $id): ?array;
    public function paginate(array $filters, int $page, int $perPage): array;
}

// 实现接口
class ExerciseRepository implements ExerciseRepositoryInterface
{
    // 具体实现
}
```

### 3. 服务层模式

```php
// Service层封装业务逻辑
class ExerciseService
{
    public function getList(array $filters, int $page, int $perPage): array
    {
        // 1. 缓存检查
        $cacheKey = $this->cacheService->generateListCacheKey(...);
        
        // 2. 从Repository获取数据
        return Cache::remember($cacheKey, 3600, function () {
            return $this->repository->paginate(...);
        });
    }
}
```

### 4. 资源转换模式

```php
// 统一的数据转换
class ExerciseResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'thumbnail' => $this->media[0]['url'] ?? null,
        ];
    }
}

// 使用
return ExerciseResource::collection($exercises);
```

## 🔧 Infrastructure层

### 1. BaseController

所有控制器的基类，提供：
- `success()` - 成功响应
- `fail()` - 失败响应
- `page()` - 分页响应
- `handleException()` - 异常处理

### 2. ApiResponse

统一的响应格式：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {...}
}
```

### 3. BaseRepository

基础数据访问方法：
- `all()` - 查询所有
- `findWhere()` - 条件查询
- `create()` - 创建
- `update()` - 更新
- `delete()` - 删除

## 📝 模块间通信

### 当前（单体）- 直接调用

```php
// User模块调用Exercise服务
$exerciseService = app(ExerciseServiceInterface::class);
$exercises = $exerciseService->getRecommended($userId);
```

### 微服务阶段 - HTTP API

```php
// User服务调用Exercise服务
$response = Http::get('http://exercise-service/api/exercises', [
    'recommended_for' => $userId
]);
```

### 微服务阶段 - 消息队列

```php
// 发布事件
event(new ExerciseViewed($exerciseId, $userId));

// 其他服务订阅事件
class UpdateRecommendation implements ShouldQueue
{
    public function handle(ExerciseViewed $event)
    {
        // 更新推荐算法
    }
}
```

## ✅ 优势总结

1. **清晰的分层** - Controller → Service → Repository → Model
2. **高内聚低耦合** - 每个模块独立，职责清晰
3. **易于测试** - 通过接口Mock，单元测试简单
4. **易于扩展** - 添加功能只需扩展模块
5. **渐进式演进** - 可以逐步拆分为微服务
